# 项目文档落位与迁移

1. 阅读 [文档地图](../../../../docs/README.md) 获取当前分类；检查目标子目录的规则与相邻代表文档。
2. 按受众、职责和变更原因决定确切文件。落位输出必须说明具体子类，不能只写 docs。
3. 模块专属契约先找对应 chart README；跨 chart 的知识按现有分类归属。已有测试 README 继续维护准确测试参数，开发指南只导航。
4. 决定迁移前搜索入链、旧标题和打包脚本。特别检查 chart README 是否进入 tgz，tracing-stack README 是否被复制到交付目录；包内需要的知识留在包内。
5. 修改后核对新旧入口、相对链接、配置键、命令和重复说法。API 表不能只因为过长移到包外。
6. 无内容不创建目录；确有既有分类不能容纳的长期内容时，说明原因与维护成本，再按任务授权处理分类变化。

项目例子：公共发布索引步骤属于跨 chart 的开发流程；tracing-stack 的离线包内容与节点导入说明属于其交付契约，应留在 chart README。联网生成离线交付物不能写成离线构建。
