# 项目职责判断

分类以仓库 [文档地图](../../../../docs/README.md) 为准。本参考提供混合内容的判断方法，不重复保存完整目录表。

| 内容变化的原因 | 判断与项目例子 |
| --- | --- |
| Agent 修改某范围时必须执行 | 放适用 AGENTS，例如 Subconverter 修改 selector 时同时核对组件 Service；架构解释链接模块 README |
| 开发者需要了解一个 chart 的参数/契约 | 放该 chart README，例如 homelab-common helper 参数与兼容性；安装包离开仓库也应可读 |
| 跨 chart 的设计关系发生变化 | 更新 docs 中的架构资料，例如 library 与第三方 common 的边界；不复制全部 API |
| 开发、测试或发布步骤变化 | 更新 docs 开发指南或已存在的专用测试说明，其他位置保留导航 |
| 同一 Agent 工作流反复执行 | 只有触发、步骤、输出和验证明确时才成为本地 skill；静态背景继续引用 docs |
| 仅此次工作尚未完成 | 放任务/issue；已有功能限制可以作为有证据的模块说明，不能与临时进度混淆 |

规则和文档发生冲突时，先确定争议是行为约束还是运行语义。约束遵循适用规则；运行语义核对模板、values、schema 和测试。明确过时的文字可以纠正；若需求与实现谁应变化无法确定，提出具体问题，不靠修改运行行为消除文档冲突。
