# Prioritize Subagent - 决策流程指南

本文档提供详细的决策流程、Subagent 类型对比和最佳实践建议。

## 详细决策流程

### 完整决策树

```
收到任务请求
    ↓
任务是否需要理解代码库结构?
    ├── 是 → 需要探索性分析吗?
    │        ├── 是 → 使用 Explore subagent
    │        └── 否 → 继续下一步
    ↓
任务是否需要 5 次以上的工具调用?
    ├── 是 → 使用 general-purpose subagent
    └── 否 → 继续下一步
↓
任务是否需要专业领域知识?
    ├── 是 → 选择专业 subagent:
    │         ├── 代码审查 → code-reviewer
    │         ├── 调试问题 → debugging-toolkit:debugger
    │         ├── 写文档 → code-documentation:docs-architect
    │         ├── 写教程 → code-documentation:tutorial-engine
    │         └── 需要规划 → Plan
    └── 否 → 继续下一步
↓
搜索目标是否明确?
    ├── 是 → 直接使用 Glob/Grep/Read 工具
    └── 否 → 使用 Explore subagent
```

## 深入分析:何时使用 Subagent

### 1. 代码探索和理解

**特征识别:**
- 需要理解多个文件之间的关系
- 需要找到特定功能的实现位置
- 需要分析架构或设计模式
- 用户询问"如何"、"在哪里"、"为什么"

**为什么使用 Subagent:**
- 需要多轮搜索和分析
- 需要综合多个来源的信息
- 需要理解上下文和依赖关系
- 探索性任务,目标可能不明确

**推荐 Subagent:** `Explore`

**Thoroughness 设置:**
- `"quick"` - 快速浏览,找到主要组件
- `"medium"` - 适度探索,理解主要流程
- `"very thorough"` - 深入探索,找到所有相关代码

---

### 2. 复杂的代码搜索

**特征识别:**
- 搜索目标不够明确
- 需要多轮搜索才能找到答案
- 需要分析搜索结果并提炼信息
- 用户请求"找到所有..."、"搜索..."

**为什么使用 Subagent:**
- 单次搜索可能无法找到所有相关代码
- 需要理解代码上下文才能判断相关性
- 可能需要使用多种搜索策略
- 需要汇总和整理搜索结果

**推荐 Subagent:** `Explore`

**提示词示例:**
```
使用 Explore subagent (medium thoroughness) 搜索项目中所有与支付相关的代码,
包括支付处理、支付验证、支付回调等。返回所有相关文件路径和简要说明。
```

---

### 3. 多步骤的复杂任务

**特征识别:**
- 需要 5 个以上的工具调用
- 需要综合分析多个来源的信息
- 需要规划并执行一系列相关操作
- 任务包含多个子任务

**为什么使用 Subagent:**
- 需要动态调整执行计划
- 需要处理执行过程中的问题
- 需要保持上下文的连贯性
- 避免在主对话中占用过多 token

**推荐 Subagent:** `general-purpose`

**提示词示例:**
```
使用 general-purpose subagent 为项目添加完整的测试覆盖:
1. 识别未测试的代码
2. 为每个模块编写单元测试
3. 集成测试到 CI/CD 流程
4. 生成测试覆盖率报告
```

---

### 4. 代码审查和优化

**特征识别:**
- 需要全面审查代码质量
- 需要检查安全漏洞
- 需要进行性能优化分析
- 需要评估最佳实践

**为什么使用 Subagent:**
- 需要专业的审查知识
- 需要全面的分析视角
- 需要结构化的审查流程
- 需要提供具体的改进建议

**推荐 Subagent:** `code-reviewer`

**提示词示例:**
```
使用 code-reviewer subagent 审查 src/auth 目录下的代码,
重点关注安全漏洞、性能问题和最佳实践违反。
```

## Subagent 类型详细对比

### Explore vs 直接搜索

| 维度 | Explore Subagent | 直接使用 Glob/Grep |
|-----|-----------------|-------------------|
| **适用场景** | 理解代码库、探索性搜索 | 精确查找、已知路径 |
| **搜索深度** | 多轮、自适应 | 单次、精确 |
| **上下文理解** | 有 | 无 |
| **结果综合** | 自动汇总 | 需要手动分析 |
| **Token 使用** | 较高 | 较低 |
| **响应时间** | 较慢 | 较快 |
| **灵活性** | 高 | 低 |

**选择建议:**
- 已知确切文件路径或模式 → 直接使用 Glob/Grep
- 需要理解和分析 → 使用 Explore

---

### general-purpose vs Plan

| 维度 | general-purpose | Plan |
|-----|-----------------|------|
| **主要目的** | 执行多步骤任务 | 规划实现方案 |
| **输出** | 执行结果 | 实施计划 |
| **与用户交互** | 较少 | 较多 |
| **适用阶段** | 实施阶段 | 规划阶段 |
| **自主性** | 高 | 中 |

**选择建议:**
- 需要规划复杂方案 → 使用 Plan
- 需要执行已知任务 → 使用 general-purpose

---

### code-reviewer vs debugging-toolkit:debugger

| 维度 | code-reviewer | debugging-toolkit:debugger |
|-----|---------------|---------------------------|
| **主要目的** | 代码质量审查 | 问题诊断和修复 |
| **关注点** | 最佳实践、安全、性能 | 错误、bug、异常 |
| **主动性** | 主动发现问题 | 响应具体问题 |
| **输出** | 审查报告、建议 | 问题原因、修复方案 |

**选择建议:**
- 主动审查代码质量 → 使用 code-reviewer
- 解决具体的 bug 或错误 → 使用 debugging-toolkit:debugger

---

### docs-architect vs tutorial-engine

| 维度 | docs-architect | tutorial-engine |
|-----|---------------|-----------------|
| **文档类型** | 技术文档、架构手册 | 教程、入门指南 |
| **目标读者** | 开发者、技术人员 | 新手、学习者 |
| **内容深度** | 深入、全面 | 渐进、示例驱动 |
| **写作风格** | 正式、技术性 | 友好、教学性 |

**选择建议:**
- 编写 API 文档、架构说明 → 使用 docs-architect
- 编写入门教程、使用指南 → 使用 tutorial-engine

---

## 判断标准和阈值

### 工具调用次数阈值

**5 次** 是一个关键阈值:

- **< 5 次**: 直接处理效率更高
- **≥ 5 次**: 考虑使用 subagent

**例外情况:**
- 即使少于 5 次,但需要复杂分析 → 使用 subagent
- 即使超过 5 次,但都是简单操作 → 可以直接处理

### 搜索明确性阈值

**明确性判断标准:**

**明确的搜索 (直接使用工具):**
- 知道确切的文件名
- 知道精确的类名或函数名
- 搜索目标具体且单一

**不明确的搜索 (使用 Explore):**
- 知道功能但不知道位置
- 需要找到"所有相关"代码
- 搜索目标是概念性的

### 复杂性评估

**低复杂度 (直接处理):**
- 单文件操作
- 简单文本替换
- 独立命令执行

**中复杂度 (视情况而定):**
- 跨文件操作 (如果明确 → 直接处理)
- 需要一些分析 (如果简单 → 直接处理)

**高复杂度 (使用 subagent):**
- 需要理解架构
- 需要多轮分析
- 需要综合判断

## 最佳实践建议

### 1. Subagent 调用技巧

**提供清晰的上下文:**

❌ **不好的示例:**
```
搜索认证代码
```

✅ **好的示例:**
```
使用 Explore subagent (medium thoroughness) 找到并理解项目中用户认证系统的实现,
包括认证流程、Token 管理、会话处理等关键组件。返回每个组件的文件路径和功能说明。
```

**明确期望的输出:**

❌ **不好的示例:**
```
分析这个项目的性能
```

✅ **好的示例:**
```
使用 code-reviewer subagent 分析项目的性能问题,重点关注:
1. 数据库查询优化
2. 缓存策略
3. 并发处理
返回具体的优化建议和代码位置。
```

---

### 2. Thoroughness 设置指南

**Explore Subagent:**

| Thoroughness | 适用场景 | 预期时间 | 预期结果 |
|-------------|---------|---------|---------|
| `"quick"` | 快速浏览,找到主要组件 | 1-2 分钟 | 主要文件和目录列表 |
| `"medium"` | 理解主要流程和功能 | 3-5 分钟 | 详细的功能说明和代码引用 |
| `"very thorough"` | 全面分析,找到所有相关代码 | 5-10 分钟 | 完整的代码映射和依赖关系 |

**选择建议:**
- 默认使用 `"medium"`
- 快速任务使用 `"quick"`
- 重要重构使用 `"very thorough"`

---

### 3. 避免 Subagent 滥用

**不必要的 Subagent 调用:**

❌ **不推荐:**
```
使用 subagent 读取 README.md
```
→ 直接使用 `Read` 工具

❌ **不推荐:**
```
使用 subagent 搜索 "User" 类
```
→ 直接使用 `Grep` 工具

**必要的 Subagent 调用:**

✅ **推荐:**
```
使用 Explore subagent 理解用户管理系统的架构
```
→ 需要多轮搜索和分析

---

### 4. Subagent 组合使用

在某些复杂任务中,可以组合使用多个 subagent:

**示例场景: 重构认证系统**

```
1. 使用 Plan subagent 规划重构方案
2. 使用 Explore subagent 分析现有实现
3. 使用 general-purpose subagent 执行重构
4. 使用 code-reviewer subagent 审查重构结果
5. 使用 docs-architect subagent 更新相关文档
```

**注意事项:**
- 每个 subagent 有独立的上下文
- 需要在主对话中协调不同 subagent 的结果
- 避免过度使用导致 token 浪费

---

### 5. 处理 Subagent 结果

**验证 Subagent 输出:**
- 检查结果是否完整
- 验证关键信息是否准确
- 确认建议是否可操作

**补充缺失信息:**
- 如果 subagent 未找到所有相关代码,手动补充
- 如果建议不够具体,要求更详细的信息
- 如果结果不够清晰,进一步追问

**整合到主对话:**
- 总结 subagent 的发现
- 提炼关键信息给用户
- 基于结果决定下一步操作

## 常见错误和纠正

### 错误 1: 过度使用 Subagent

**症状:**
- 即使读取单个文件也使用 subagent
- 简单的搜索也启动 subagent
- 频繁调用 subagent 处理琐碎任务

**纠正:**
- 评估任务复杂度
- 优先考虑直接使用工具
- 保留 subagent 给真正复杂的任务

---

### 错误 2: Subagent 类型选择不当

**症状:**
- 使用 Explore 处理明确的文件查找
- 使用 general-purpose 处理需要规划的任务
- 使用 code-reviewer 处理 bug 修复

**纠正:**
- 理解每个 subagent 的专长
- 根据任务性质选择合适的类型
- 参考本文档的对比表格

---

### 错误 3: 缺乏清晰的上下文

**症状:**
- Subagent 返回不相关的结果
- 需要多轮交互才能明确需求
- Subagent 无法理解任务目标

**纠正:**
- 提供详细的任务描述
- 明确期望的输出格式
- 说明任务的背景和目的

---

### 错误 4: 忽视 Subagent 的局限性

**症状:**
- 期望 subagent 处理需要实时反馈的任务
- 要求 subagent 访问外部资源
- 假设 subagent 有完整的上下文

**纠正:**
- 理解 subagent 是独立的进程
- 避免 subagent 需要与主对话频繁交互
- 在主对话中处理需要协调的任务

---

## 总结

**核心原则:**
- Subagent 为复杂任务设计,不是所有任务都需要
- 理解每个 subagent 的专长和适用场景
- 提供清晰的上下文和期望的输出
- 避免过度使用 subagent

**快速检查清单:**
- [ ] 任务是否需要理解代码库? → Explore
- [ ] 是否需要 5+ 次工具调用? → general-purpose
- [ ] 是否需要专业知识? → 专业 subagent
- [ ] 搜索目标是否明确? → 直接使用工具
- [ ] 是否有更好的 subagent 选择? → 参考对比表
