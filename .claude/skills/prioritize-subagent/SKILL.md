# 优先使用 Subagent

## 核心原则

**复杂任务使用 Subagent,简单任务直接处理。**

Subagent 专门用于需要代码库理解、复杂分析或多步骤操作的任务。对于简单的单步操作(读取文件、简单编辑),直接使用工具更高效。

## 快速决策

在开始任务前,问自己以下 4 个问题:

### 1. 这个任务是否需要理解代码库的多个部分?

- **是** → 使用 `Explore` subagent
- **否** → 考虑直接使用工具

### 2. 这个任务是否需要 5 次以上的工具调用?

- **是** → 使用 `general-purpose` subagent
- **否** → 考虑直接使用工具

### 3. 这个任务是否需要复杂的分析和综合?

- **是** → 使用相应的专业 subagent
- **否** → 考虑直接使用工具

### 4. 搜索目标是否明确且具体?

- **是** → 可以直接使用 Glob/Grep
- **否** → 使用 `Explore` subagent

## Subagent 类型参考表

| Subagent 类型                    | 用途        | 使用场景           |
|--------------------------------|-----------|----------------|
| **Explore**                    | 代码探索、架构理解 | "理解代码库"、"分析架构" |
| **general-purpose**            | 通用多步骤任务   | 复杂重构、多文件操作     |
| **code-reviewer**              | 代码审查和质量检查 | 安全检查、性能优化      |
| **debugging-toolkit:debugger** | 调试和错误诊断   | 修复 bug、错误分析    |

## 何时使用 Subagent

### ✅ 使用 Subagent

- 代码探索和理解:"解释认证系统"、"项目整体架构"
- 复杂搜索:"所有性能问题"、"所有使用 Redis 的地方"
- 多步骤任务:"重构认证系统"、"添加完整测试覆盖"
- 代码审查:"审查 PR"、"检查安全漏洞"

### ❌ 直接使用工具

- 单步操作:"读取 config.yaml"、"运行测试"
- 精确查找:"找到所有 .md 文件"
- 简单搜索:"搜索 'User' 类的定义"

## 最佳实践

1. **优先使用 subagent**: 当不确定时,优先考虑使用 subagent
2. **提供清晰的上下文**: 在 prompt 中提供详细的任务描述和期望的输出
3. **选择合适的 subagent 类型**: 根据任务性质选择最匹配的 subagent
4. **设置适当的 thoroughness**: 对于 Explore 任务,根据需求设置探索深度
5. **避免过度使用**: 对于简单的单步操作,直接使用工具更高效
